# 后续阶段：ReplayKit 与画中画

当前交付范围为操作按钮/快捷指令触发的单次截图翻译。结果展示在本 App 的 SwiftUI 界面，不是任意 App 上方的全屏透明覆盖；iOS 没有向普通第三方应用开放任意全局交互式悬浮层 API。

## ReplayKit

可研究用户主动启动系统屏幕广播后的 Broadcast Upload Extension。扩展接收视频帧，裁剪/缩放并降低 OCR 采样频率，通过 App Group 与主应用交换结果；这需要新增扩展、签名能力和用户明确授权。

关键约束：系统广播提示及结束控制不可隐藏；扩展的内存、执行时间和后台生命周期有限；受保护内容可能无法采集；不能持续上传每一帧而忽略用户成本与隐私。先用本地 Vision 验证 0.5–1 fps、变更检测、延迟、电量与扩展内存，再考虑显式开启的 AI 请求预算、取消和背压。广播采集能力并不等于拥有跨 App 覆盖层能力。

## 画中画

AVKit 的画中画用于系统管理的视频播放等受支持用途。可评估将翻译渲染为视频帧供用户查看，但窗口大小、位置、交互和生命周期由系统控制，无法覆盖每个原始文字位置，也不能假定任意 SwiftUI 视图可以直接作为 PiP 内容。需要原型验证 API 合规用途、后台播放和审核要求。

## 开始下一阶段的门槛

先完成本次截图流程的真机验收。之后独立 PR 引入广播扩展原型，只用本地 OCR，验证用户开始/停止、受保护内容、旋转、内存和功耗，再评估 PiP 输出是否有实际可用性。任何云端实时方案都必须明确发送范围、频率、费用上限和用户撤销行为；未通过验证前不宣传实时全屏覆盖已经实现。
