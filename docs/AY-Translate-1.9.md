# AY Translate 1.9

## 依据与范围

1.8 真机日志中，失败记录在 reading 阶段约 0.51 秒内收到 4 次内存警告，采样 footprint 为 198,723,568 字节，可用预算 31,963,152 字节；前一轮虽完成，采样 footprint 也达到约 196 MB。这比模拟器小素材高得多。不能用模拟器无警告证明真机不会被系统终止，也不能仅由四条记录断定存在固定速度的泄漏。

用户另提供整段/部分列仍保留日文的漫画对照。本轮同时处理大图识别的资源使用与漏列，不把识别降成低分辨率整图，也不修改选定的目标语言。

## 修改

- 分享扩展在串行队列真正取得执行权后，重新读取当前内存预算。可用预算低于 96 MiB、footprint 达到 140 MiB 或近期有警告时提前采用较小窗口；模拟器返回的零预算视为未知。
- 原生文档识别改为保留源像素的重叠窗口，正常窗口 1536，压力窗口 1024，逐个执行并合并坐标/字形信息。使用公开的支持设备列表选择 CPU（仅限框架声明支持的计算阶段），补识别也使用 CPU，避免为不同识别请求额外建立加速器缓冲。主 App 保留整图路径。实际真机耗时与内存改善幅度需复测。
- 局部漏列最多检查 32 列，保留每批四列的串行执行，避免复杂多气泡页面被原来的 12 列上限截断。分块重叠用于恢复跨边界文字；原图未得到完整译文时仍保留。
- 本地字形检测的连通域遍历只保留尚未处理的队列前沿，大面积黑色截图边缘不再需要保留每个已经扫描过的像素索引。
- 显式清空缩放子控制器的 SwiftUI 图片、关闭回调及子视图；系统即使暂时保留已关闭的控制器，也不应因此继续保留整张截图。用小型 Core Graphics 位图取色，移除每轮创建的 Core Image 上下文。
- 诊断增加有上限的识别步骤内存检查点，保留导入起点及近期检查点；迟到的旧请求不能写入新一轮记录。仍不保存识别文字、图片、API Key 或供应商响应。

## 验证

新增：用户日志预算的提前分块决策、窗口覆盖与上限、大面积黑边扫描、嵌套缩放控制器图片释放、检查点隔离、15 个带小号注音的竖排气泡、六次不同的 1170 × 2532 图片真实分享调用。实际构建与通过情况见 PR，不能将新增测试本身视为已经通过。

模拟器的预算、神经网络后端和系统回收行为与真机不同。真实漫画覆盖率、Feather 重签后的连续快捷指令截图、外部 AI 延迟仍需真机验证。

公开 API 参考：[Vision 支持的计算设备](https://developer.apple.com/documentation/vision/visionrequest/supportedcomputestagedevices)、[指定计算设备](https://developer.apple.com/documentation/vision/visionrequest/setcomputedevice(_:for:))。
