# AY Translate 1.4 开发记录

本轮聚焦 iPhone 识别、速度、背景和日常操作。iPad 真机验收按用户安排后置；保留已有自适应布局及自动化回归。

## 实现

- iOS 26 原生 `RecognizeDocumentsRequest` 返回文字行、竖排方向和字形位置，正常路径不再连续执行整图、四块裁剪、最多 32 次逐列 OCR。失败时保留旧的本地识别回退。官方 API：https://developer.apple.com/documentation/vision/recognizedocumentsrequest 。未声称与系统截图翻译使用同一私有实现。
- AI OCR 与翻译使用紧凑的请求内 ID，完整校验后映射回原位置；每批 40 个区域、最多两批并行，仍带整屏上下文。已安装苹果模型不再重复调用准备步骤。同图切换翻译器复用本机 OCR，关闭释放缓存。AI OCR/翻译/重试共用无 Cookie、无磁盘缓存的临时连接池。
- 长按原图图标的菜单可查看识别/翻译耗时。日志只记录耗时、区域数，不包含文字、图片、接口或密钥。模拟器基准不等于真机 1 秒承诺。
- 默认背景改为局部对比笔画遮罩与周围像素重建，仅修改遮罩内像素；不再把整个原文矩形填成灰色或黑色。文字加细描边保持复杂背景可读。高对比模式仍由用户主动选择。不能恢复被文字永久遮住的真实图像，低置信度图片边缘保守保留。
- 竖排短译文按源区域列数均衡分列、居中，不再全部挤在第一列顶端。保留基于原字大小的手动缩放，超长内容不强制缩成小字。
- 首页只留一个图片导入入口、语言选择；快捷指令设置集中到设置。显示、隐私、历史各自进入二级页面。统一显示名为 AY Translate，保留内部 Bundle ID/Keychain 身份确保覆盖升级不丢配置。新快捷指令使用蓝色。
- 服务商使用打包在本机的品牌图标，来源/许可见 ProviderIcons.md。
- 可选 iCloud KVS 同步语言、显示、引擎和服务定义；按设置独立时间戳合并，默认关闭。首次在已配置设备点击一次“将本机设置存入 iCloud”，后续修改自动同步；新设备先下载，避免初次启动的空配置覆盖云端。API Key、历史、截图、云端授权不参与同步；不同设备首次仍需填 Key/许可。远端服务地址改变时清除旧本机 Key，避免跨地址泄漏。iCloud 账号改变会关闭同步并提示重新选择。需要自签描述文件保留 KVS 权限，同账号且签名使用一致的云容器标识。Feather 缺少此能力时仍可本地使用和手动转移配置。

## 验证与边界

Linux 核心回归覆盖笔画恢复、未修改背景像素、竖排均衡、云设置白名单和冲突合并、紧凑 ID/批次。macOS GitHub Actions 验证原生识别、蓝色签名快捷指令、iOS 编译、真实共享入口及截图附件。最终运行结果和 IPA 链接写入 PR。

上一版最终 run 41903051854 的 iOS 测试失败来自模拟器目标暂不可用及 Accessibility 初始化超时；Release IPA 构建、核心测试和独立 iPad/Vision 已通过。新工作流增加明确的 destination 等待时间，仍保留原生功能断言。

待真机确认：用户漫画的实际识别完整度、原图背景重建视觉、各引擎冷/热耗时、Feather 的 iCloud 权限。系统 Share 宿主仍可能出现卡片边界，未宣称解决全屏限制；没有发布 Release。

首轮新原生测试：macOS 26 Intel 共 76 项通过，三句竖排日文全部返回；合成 900×1600 三列图冷启动新 API 3.625 秒、旧路径 4.015 秒（Debug 测试环境）。此数据不是 iPhone 性能承诺；后续补充热启动及 iOS 渲染测试。
