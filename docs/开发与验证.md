# 单次截图翻译：开发与验收

## 当前实现

继续使用原有 SwiftUI/Xcode 工程，快捷指令为 `Take Screenshot → Share with Translate Screen`，通过 Share 扩展显示结果。1.2.1 修正了旧版将扩展注册为 Action 类型、导致快捷指令提示“没有共享扩展”的问题。系统活动面板仍以卡片呈现，完整无边框全屏效果尚未完成。默认 Apple Vision + Apple Translation，无账号、无广告、无 API Key；语言模型下载由系统管理。截图结果可关闭、原图/译图切换、全文阅读、复制、连续双指缩放、拖动平移、重置缩放；字号按原文行高估算，设置中的倍率在各自原字号上缩放。较长译文适度调整排版，点击区域可展开完整译文。

OCR 和翻译可分别选择 AI：在服务列表保存多个自定义名称、OpenAI 兼容 HTTPS Base URL、模型和独立密钥，再分别选用，切换保留其他配置。Base URL 应包含供应商要求的前缀（例如 `/v1`）；也接受完整 `/chat/completions` 地址。支持不需要 Key 的自建 HTTPS 服务，不支持绕过 TLS 验证或任意明文 HTTP。全屏扩展、语言、图标及快捷指令签名限制详见 [1.2 调查与交付说明](全屏扩展与快捷指令调查.md)。

### 位置与上下文

- Vision 保持 `.accurate`、语言校正、自动语言检测，提取真实屏幕位置。
- AI OCR 接收图片及本地锚点，按稳定 ID 返回文字与归一化坐标。仅能通过锚点或唯一文字/位置匹配验证的区域用于覆盖，始终采用 Vision 的位置。
- 没有可靠位置的 AI 文字只进入全文阅读，并显示提示；不会因为模型给出了合法数值坐标就当成准确坐标。没有任何本地锚点时自动进入全文模式。
- AI OCR 服务失败且已有本地识别结果时回退 Vision；完全识别失败也保留本次截图，支持换引擎重试。
- 两种翻译共用相邻行分组，减少拆散同一句话；菜单、不同列和明显分隔的段落分开处理。质量优先允许更长的段落；速度优先使用 Apple 低延迟策略。中文连续行不插入多余空格。
- AI 翻译同时收到段落和有限长度的整屏上下文。按 ID 校验每批输出，缺失、重复、陌生 ID、空译文、截断输出均报错，不把部分结果伪装成成功。
- 通过 `ProcessingServices` 与纯 Foundation 核心扩展服务，不需要更换 UI 或引入供应商 SDK。

### 隐私和成本

只有用户选择 AI 引擎、配置服务并确认数据目的地后才发送数据。AI OCR 发图片，AI 翻译发文字；两者可独立选用。许可绑定确切 endpoint 和模型，修改配置后重新确认，可在隐私设置撤销。正在执行的请求无法从供应商处撤回。

密钥仅存 `WhenUnlockedThisDeviceOnly` Keychain，不进入 UserDefaults、历史记录、提示词、日志或源码。更换 endpoint 时清除旧密钥，除非用户同时输入替代值。请求使用临时 URLSession，不持久化 HTTP 缓存、Cookie 或认证信息，拒绝重定向，避免向新地址转交图片和认证头。错误提示不回显供应商响应正文。

默认关闭历史；关闭结果释放当前截图，关闭历史会删除历史内容并隐藏底部历史标签。共享扩展通过系统图片提供器读取输入，不使用图片落盘交接，结束请求后退出。备用“在 App 中翻译截图”动作使用受文件保护的临时交接图片，读取后立即删除，120 秒以上不再导入；异常图片也会删除。没有向相册写入的功能。第三方 AI 的费用、保留期限和可用性由供应商决定，免费 App 不代表外部调用免费。

## 本地和 CI 测试

纯核心测试使用生产源码 `ScreenTranslate/Core`，没有模拟替代算法：

```bash
swift test --jobs 3
```

涵盖归一化坐标转换、错误/重复 AI 区域、锚点与不可靠位置回退、段落分组、连续缩放/平移边界、HTTP 请求格式、上下文分批、输出完整性、API 错误脱敏、取消、重定向策略、超限输入输出。HTTP 测试使用本地 URLProtocol，不需要真实服务或付费密钥。

`ScreenTranslateTests` 为 iOS 宿主测试，检查默认本地路径不读取密钥、不调用 AI、不保存历史，OCR 失败重试、云端许可、更换目的地、关闭后迟到请求不能更新 UI、AI OCR 本地回退、实际 Vision OCR、临时图片清理和真实 Keychain 的增删改查。

```bash
xcodebuild test -project ScreenTranslate.xcodeproj -scheme ScreenTranslate \
  -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.5' \
  -parallel-testing-enabled NO -jobs 3 \
  -derivedDataPath /tmp/ScreenTranslateDerivedData
```

目的地应替换为本机实际安装的设备。需要 macOS、Xcode 26.6 和 iOS 26.5 SDK/Simulator；Linux 无法编译 UIKit/SwiftUI/Translation 或运行这些测试。CI 使用 `.github/scripts/simulator-destination.py` 选择满足最低系统版本的可用 iPhone，不硬编码不存在的设备。

## GitHub Actions 和 IPA

`.github/workflows/release-ipa.yml` 在 PR、版本标签或手动触发时执行：环境诊断 → 核心测试 → Release 无签名构建/打包/上传 → iOS 宿主与 UI 测试编译 → Xcode 启动模拟器并执行 iOS 测试。`pipefail` 保留测试和 xcodebuild 的真实退出码；失败时仍尽可能上传日志和 xcresult。编译与执行分离；Xcode 负责模拟器首次数据迁移/启动，整个测试执行阶段设定 25 分钟上限，单项测试也设定执行超时。实测 Intel 冷启动与 Metal 初始化约需九分钟，另有测试和报告收尾时间；避免额外的短时 simctl 预启动检查将冷启动误判为源码失败。结束后清理本任务启动的模拟器。即使后续模拟器测试失败，已编译的 IPA 仍可供人工排查；整体 CI 仍标记失败，标签 Release 也不会发布，不能把有产物当作测试通过。

默认 `macos-26-intel`，固定使用 `/Applications/Xcode_26.6.app`，限制编译并行度为 3。2026-11-03 官方 runner-images 文档确认该标签及 Xcode 26.6/iOS 26.5 存在，仓库先前也有 Intel 成功运行。原 ARM64 `macos-26` 两次失败运行都没有获得 runner、没有执行任何步骤；检查注释明确包含 `The job was not acquired by Runner of type hosted even after multiple attempts` 和 macOS arm64 容量提示；这类结果属于调度/资源问题，不能视为编译诊断。新任务也可能遇到服务端容量或配额限制，应查看 Jobs、分配情况和日志。

手动运行时可改选标准 `macos-26` 作为备用；没有使用需要额外费用的 large/xlarge 标签。不能承诺服务器必定分配资源，也不通过更换源码来“修复”未启动的任务。

获取 IPA：进入本 PR 的 Checks 或仓库 Actions → Build IPA → 成功运行 → Artifacts → `TranslateScreen-<版本>-unsigned`。下载并解压后包含 `.ipa` 与 `.sha256`。未签名 IPA 不能直接安装在普通 iPhone，需要自己的 Apple 签名/侧载工具。PR 和手动运行只生成产物；仅用户主动推送 `v*` 标签时保留原有 Release 发布行为。

## 人工验收和未完成项目

- 真机首次语言包下载、Apple Translation 的完整翻译质量/速度和离线行为，需 iOS 26.5+ 设备验证；Simulator 的工作流测试不会伪造语言模型下载成功。
- 使用自选供应商测试实际多模态 OCR 和 AI 翻译；自动化只覆盖协议与错误处理，不声称所有兼容服务都已实测。长截图可能达到输入/输出上限，需要缩小截图或改用 Apple。
- 真机 Shortcuts/操作按钮一键截图、横屏截图、阿拉伯语 RTL、多列复杂界面、无文字截图、超长译文、VoiceOver、旋转和手势体验需要人工验收。
- 回归确认默认无 Key 可用、未同意前无远程请求、分别使用两种云端引擎时发送内容正确、关闭不留当前图片、关闭历史清除记录。
- 本阶段是单次截图，不提供任意 App 上方的全屏透明悬浮层。实时方案单独评估，见 [实时翻译评估](实时翻译评估.md)。

本地及远程的实际测试结果、构建链接和未通过原因记录在 PR 中。不能用 Linux 语法检查代替 macOS 构建，也不能把排队/未执行的测试写成通过。
